Gateway agent

Receives human requests, starts supported task cards and returns their results. Monitoring and scientific adjustment run as separate cards; the gateway is not itself the stationary lock or an optimizer.

Before starting

The selected provider CLI and authentication must be available to the service user. Select an execution profile or provider, model and supported effort. Starting or reconnecting this card does not restart a laser lock.

Connections and history

A card keeps a separate conversation per provider. Reconnecting resumes that conversation. The UI names the role Gateway agent. Stable routing IDs remain available in technical details and archived records. A session in history is not proof that its worker is currently running.

How to use it

Use the agent-request card or the shared native terminal/Web connection. OpenCode uses the same authenticated server and conversation; Claude and Codex request Remote Control where supported. The connection status, not the setting alone, confirms availability.

Measurements and authority

This card does not directly acquire a waveform or drive an output. Its scoped tools read the assigned laser, submit registered operations and inspect owner-confirmed results. Safety changes still require exact human approval. Agent replies and provider claims do not prove that hardware changed.

Failures and records

Failures use the gateway and configured Teams notification card. Questions and verified recovery are shown in Failure history and agent questions. Session history, request outcomes and PDF reports are kept in the laser data directory; shared code remains read-only.

ゲートウェイエージェント

人間の依頼を受け、対応するタスクカードを起動し、その結果を返します。監視・実機調整は別のカードです。ゲートウェイ自身が定常ロックや最適化を行うわけではありません。

開始条件

サービス実行ユーザーが選択したCLIと認証を利用できる必要があります。実行プロファイル、またはプロバイダー・モデル・対応するEffortを選びます。開始・再接続でレーザーロックは再起動しません。

接続と履歴

プロバイダーごとに会話を保存し、再接続時は同じ会話を継続します。画面ではゲートウェイエージェントと表示します。接続用の内部IDは技術詳細と過去記録に保持します。履歴があるだけでは稼働中とは限りません。

使い方

agent-requestカード、または共有の端末・Web接続から依頼します。OpenCodeは同じ認証付きサーバーと会話に接続します。Claude・Codexは対応時にRemote Controlを要求します。実際の利用可否は接続状態で確認してください。

測定と権限

このカードが直接波形を取得したり出力を書き換えたりすることはありません。担当レーザーの限定ツールで状態を読み、登録済み操作を依頼し、ownerの確認済み結果を調べます。安全設定の変更は具体的な差分に対する人間の承認が必要です。エージェントの返答だけを実機変更の証拠にはしません。

失敗と記録

失敗はゲートウェイと設定済みTeams通知カードへ渡します。相談と復旧確認は「失敗履歴・エージェントへの回答」で行います。接続履歴、依頼結果、PDFレポートはレーザーのデータ領域に保存し、共通コードは読取り専用です。

网关代理

接收用户请求，启动支持的任务卡并返回结果。监控与实际调整由独立卡执行；网关本身不是稳态锁定器或优化器。

启动条件

服务用户必须能够使用所选CLI和认证。请选择执行配置，或提供商、模型及受支持的推理强度。启动或重连此卡不会重启激光锁定。

连接与历史

每个提供商保留独立会话，重连会继续原会话。界面显示为网关代理。稳定的路由ID保留在技术详情和历史记录中。历史记录不代表当前工作进程正在运行。

使用方法

通过agent-request卡，或共享终端和Web连接发送请求。OpenCode共享同一个经过认证的服务器和会话。Claude和Codex在支持时请求Remote Control。请以实际连接状态确认可用性。

测量与权限

此卡不直接采集波形或修改输出。限定工具用于读取负责的激光状态、提交已注册操作并检查owner确认的结果。安全设置变更仍需用户批准具体差异。代理回复不等于硬件已完成操作。

失败与记录

失败会转交网关及已配置的Teams通知卡。在失败历史和代理问题页面回答问题并验证恢复。会话历史、请求结果和PDF报告保存在激光数据目录中；共享代码保持只读。
