ECDL復旧手順の作成

plan.ecdl_recovery は、成功した大域マップと選択枝から、準備経路・走査方向・元の光学状態の検証条件をまとめるカードです。機器を開かず、走っている定常ロックと並行して実行できます。

入力と計画

map_ref に同じレーザーの成功したマップjob IDと artifact_sha256 を指定します。指定枝がなければマップの選択枝を使います。元のTEC/PZT文脈、conditioning、走査開始点への準備、その後の選択点までの一方向経路を保存します。元の電流に戻すだけの手順ではありません。

map_ref:
  job_id: map-job-id
  sha256: "マップ成果に記録された64桁のSHA256"
selected_branch_id: null
selection_author: automatic
tolerance_hz: null
hop_threshold_hz: null
stable_s: 5
confirm_samples: 3
metric_limits: {}

tolerance_hz は元の光学状態へ戻ったと認める周波数幅、hop_threshold_hz はホップ確認に使う変化幅です。どちらも測定目的・装置に応じて明示します。metric_limits は追加の光学指標上限、stable_s と confirm_samples は新しい有効取得で満たす確認条件です。

成果は提案

recovery-plan.json に元マップのSHA256、枝、校正・判定文脈、手順、検証条件を保存します。生成成功は復旧成功の実証ではなく、verified: false です。実証は 意図的ホップ・復旧試験で別の成果として記録します。ホップ機構を自動断定しません。

定常運転への受け渡し

定常ロックにはこの計画だけでなく、同じ計画に基づく実ホップ復旧試験の成功成果も対で渡します。計画と試験のSHA256、レーザー、出発点・光学文脈を照合します。TEC/PZTを変更して取得した別文脈へ、元の証拠を自動的に引き延ばしません。
