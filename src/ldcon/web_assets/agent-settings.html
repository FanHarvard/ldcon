Execution profiles

Revision not loaded

Define profiles here, then assign them in the difficulty routing table above. Names such as basic or deep in a Profile ID have no special meaning.

Profiles select a provider, exact model and resource budgets. Saved changes apply to new sessions and tasks; active runs keep their selected profile.

Model and effort choices come from the locally verified capability list. Account access is checked when a task connects. Provider default leaves effort to that provider. Existing running tasks are unchanged.

Resource budgets: Max turns / Input bytes

Max turns caps the task’s model/decision rounds; it does not count hourly monitor wakeups. Input bytes caps the UTF-8 task instructions and evidence bundle, not tokens or total conversation history. Keep the saved budgets unless a task reaches its limit. The current adjustment profiles use 64 turns and 262144 bytes; reducing these can prevent a useful study. These budgets never expand device authority.

Authentication is not checked here. Executable availability does not prove login, model access or permission to run a task. This page does not connect to a model.

Notification policy

Revision not loaded

Automatic messages are brief English summaries. Human replies retain the original request language. Detailed evidence stays in local records at every preset.

Quiet

Brief outcomes and actionable changes. Intermediate progress stays local.

Standard

Outcomes with selected quantities. Routine progress is combined into completion summaries.

Investigation

Also reports starts and bounded milestones, with cooldown and relevant uncertainty.

New faults, unexpected stops and required human decisions remain immediate. Unchanged healthy checks stay local. Repeated events and questions are deduplicated.

Per-laser and temporary task overrides · advanced JSON

Overrides may set preset and progress_interval_s. Unspecified fields inherit the previous scope.

{"laser-example": {"preset": "quiet"}}
{"task-example": {"laser_id": "laser-example", "policy": {"preset": "investigation"}, "expires_unix_s": 1800000000, "completed": false}}

Use the actual task ID. A task override expires at completion or its optional Unix deadline. Expired overrides remain visible for audit and no longer affect delivery.
